# V2EX 每日签到

私有仓库，通过 GitHub Actions 每天自动领取 V2EX 每日登录奖励。

## 组成

| 文件 | 作用 |
|---|---|
| `v2ex_auto.py` | 签到脚本。纯标准库实现，无第三方依赖 |
| `.github/workflows/checkin.yml` | 定时任务定义 |

## 运行时间

北京时间每天两次：

| 时间（北京） | cron（UTC） | 作用 |
|---|---|---|
| 14:30 | `30 6 * * *` | 主任务 |
| 20:30 | `30 12 * * *` | 兜底 |

合并写法：`cron: '30 6,12 * * *'`

**为什么不放在早上 8:30——这是实测结论，不是偏好。**

GitHub Actions 的 scheduled workflow 在高负载时会被延迟甚至丢弃。官方文档写明
「high load times include the start of every hour」，且「负载足够高时部分排队任务会被丢弃」。
UTC 00:00–02:00 是全球用户集中排「每天零点」任务的峰值区间。

实测四组数据：

| cron (UTC) | 北京 | 实际结果 |
|---|---|---|
| 00:30 | 08:30 | 11/2、11/3 均未执行（被丢弃）；旧 fork 延迟 6h04m |
| 01:40 | 09:40 | 旧 fork 延迟 7h26m |
| 06:30 | 14:30 | 准点执行，仅差 1 分钟 |

放在 UTC 06:30 之后即避开该区间。V2EX 奖励全天可领，下午执行不损失奖励。

脚本幂等：已领取则立即退出，不会重复请求 redeem。

## 运行记录

每次运行会把结果追加到 `logs/YYYY-MM.md` 并提交回仓库，所以：

- 直接在仓库里就能看到哪天几点跑了、结果如何，不必翻 Actions 网页
- 仓库每天都有提交，**自动规避「60 天无活动停用定时任务」的规则**，无需手动保活

日志格式：以北京时间的 `## YYYY-MM-DD HH:MM:SS（北京） 事件=<event>` 为标题，
下面附本次运行的完整输出。

> 注意：本 workflow 不能添加 `push` 触发器，否则日志提交会触发自身形成无限循环。

## 需要的 Secrets

在 `Settings → Secrets and variables → Actions` 中配置两项：

| 名称 | 内容 |
|---|---|
| `V2EX_COOKIES` | 浏览器登录 v2ex.com 后，请求头里的完整 Cookie 字符串 |
| `V2EX_TOTP_SECRET` | 两步验证的 TOTP 密钥（Base32） |

`V2EX_TOTP_SECRET` 用于在 Actions 每次以新 IP 登录时自动通过 `/2fa` 校验。
若不配置，则仅当账号未开启两步验证时可用。

## 失效排查

| 日志报错 | 含义 | 处理 |
|---|---|---|
| 登录态无效 / Cookie 可能已经失效 | `A2` 过期 | 重新导出 Cookie，更新 `V2EX_COOKIES` |
| 两步验证未通过 | TOTP 密钥不匹配 | 重新绑定 2FA 并更新 `V2EX_TOTP_SECRET` |
| 签到请求失败 | Cloudflare 拦截或未到发奖时间 | 重跑一次；确认在 8 点后 |

改密码、在其它设备点「退出登录」都会让 `A2` 立即失效。

## 保活

GitHub 会在仓库连续 **60 天无提交**后自动停用定时任务，且不会发出任何通知。
收到保活提醒后，在本仓库任意提交一次（或手动 Run workflow）即可重置计时。
